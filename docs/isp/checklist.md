# ISP 遵守項目（チェックリスト）

この文書は、ISP（in silico perturbation、計算機上で遺伝子を1つ削除して細胞の状態変化を見る解析）を、
複数のエージェントと複数の PC で並行して進めるために守る項目をまとめたものです。
この文書は、規則を前提にした「作業の決まりごと」です。規則の正典は各ページにあり、
一覧は[執筆者名簿とページ担当](owners.md) §4 の表にあります。

## 最優先（どの作業でも。2026-09-17 追加）

規則の本文は[記述ルール](style-guide.md) の「最優先の遵守項目」にあります。
この 4 項目は、この文書の他のどの項目よりも先に確認します。

- [ ] **数値を変える処理を入れたとき、値を変えていないことを実測で確かめたか。** 確かめ方は
  [記述ルール](style-guide.md) の「最優先の遵守項目」にあります。
- [ ] **辻褄合わせをしていないか。** 前提が崩れたら、**黙って通さず停止**させましたか。
- [ ] **「実行が通った」を「値が正しい」の根拠にしていないか。** 通ったときは、何を確かめたのかを添えましたか。
- [ ] **誤りを見つけたとき、訂正前と訂正後の数値を並べて報告したか。** コミットメッセージに欠陥として残しましたか。

## 0. 最初に言葉の意味

読み進める前に、この文書で使う言葉を説明します。

- **符号が反転する**: 同じ遺伝子について、V2-104M と V2-316M という2つのモデルが、
  正と負で逆の結論を出してしまうことです。
- **摂動できる細胞数**: その遺伝子を持っていて、実際に削除操作の対象になった細胞の数です。少ないと結果が安定しません。
- **検出率**: 対象の細胞のうち、その遺伝子を持っている細胞の割合です。低いと摂動できる細胞が少なくなります。
- **E4**: 遺伝子ごとの測定可能性についての項目です。摂動できる細胞からブートストラップ信頼区間を求め、
  その幅が値そのものより小さいかどうかで判定します。
  「500 個以上」という線は以前の目安であり、現在は使いません（[評価基準](criteria.md) の E4）。
- **系統マーカー**: CD8A や CD4 のように、その細胞が何の細胞であるかを決めている遺伝子です。
- **文献の証拠の第1層と第2層**: 第1層は自分で論文を取得して要旨を読んだもの、
  第2層は別のエージェントに調べさせて PMID だけを機械的に確認したものです。
- **受信箱（廃止）**: かつて担当外のページへの依頼を書き残した場所です。2026-09-25 に担当を AG-GH 1 名に一本化し、廃止しました。

## A. 作業の前に必ず行うこと

## B. 分析のときに守ること

### B-1. 解析を始める前に確認すること

解析前の項目は[評価基準](criteria.md)の「3. 実行前後の手順」と「4. 記録する項目」が正式なリストです。
この文書では内容を繰り返しません。とくに次の 3 つは後から取り戻せないので、必ず実行してください。

- [ ] **対象とする状態の組み合わせが十分に離れているかを測る（E5）。** 埋め込み空間での相対距離が小さいと、
  遺伝子を削除しても信号が出ません。
- [ ] **遺伝子ごとに、摂動できる細胞の数を数えて記録する。** 少ない遺伝子は順位を解釈しないと記録に書きます。
  E4 の判定は、その数からブートストラップ信頼区間を求めて行います（[評価基準](criteria.md) の E4）。
- [ ] **対照遺伝子と陽性対照を入れる（E3）。** 対照遺伝子は ACTB や GAPDH のように削除しても状態が変わらないはずの遺伝子、
  陽性対照は対象の細胞で実際に発現している遺伝子から選びます。
- [ ] **対照遺伝子も検出率の条件（20% 以上）を満たすものを選ぶ。** 満たさない場合は E3 を「未検証」とし、
  対照として機能していないことを明記します。実測では GAPDH が GSE174367 で 15.0%（412 個）、
  PD アトラスで 15.8%、ACTB も PD アトラスで 18.1% と条件を満たさず、対照として機能していません
  （[評価基準](criteria.md) の §2-1-2 を参照）。
- [ ] **null 遺伝子を 20 個以上選び、順位位置を対象に合わせたか。** そろえ方は[方法・共通設定](methods.md) の §8-2、
  p 値の下限は同 §8-7 です。1 個の対照では偶然のばらつきを測れません。

### B-2. 結果を解釈するときに守ること

- [ ] **1つのモデルだけで標的候補を報告しない。** 今回の測定では、モデルを替えると 55 個の遺伝子のうち
  18 個で符号が反転しました。つまり候補リストは、モデルの選び方で入れ替わります。
- [ ] **2つのモデルの結果が一致したことを「独立に再現した」と呼ばない。** 2つのモデルは同じトークン化と
  ランク符号化を共有しているため、発現量に由来する効果は両方で同じように現れます。
  独立した確認には、CRISPRi や Perturb-seq のような別の手法が必要です。
- [ ] **発現が少ない遺伝子の順位を解釈しない。** 検出率と摂動できる細胞数を必ず併記し、
  少ない場合は「判定不能」と書きます。
- [ ] **系統マーカーは標的候補にしない。** CD8A、CD4、CD19 などを削除すると、細胞の種類そのものが
  崩れる方向に結果が動くため、治療の標的として読むことはできません。
- [ ] **指標が何を測っているかを必ず添える。** 測っているのは「脾臓の免疫細胞が WT の状態にどれだけ近いか」
  であり、「病気そのものが良くなったか」ではありません。
- [ ] **null 分布を 1 つのパネル・操作・モデルにつき 1 回だけ作り、多数の候補で共有したか。** コストの大部分は
  null 分布です。候補ごとに null を作り直すと解像度が落ちます（[方法・共通設定](methods.md) の §9-1）。
- [ ] **候補の選抜を「有望さの予測」で行っていないか。** 静的な特徴量（交差検証 ρ = +0.49）、100 細胞の前段
  （ρ = +0.001）、null 10 個の前段（ρ = +0.205）はいずれも本規模の順位を再現できませんでした（同 §9-2）。
  選抜には共有した null 分布に対する検定を使ってください。
- [ ] **陽性対照（広く効く制御遺伝子）を入れたか。** 転写因子の過剰発現のような陽性対照がないと、
  陰性の結果が「対象が効かない」のか「方法に感度がない」のかを区別できません（[方法・共通設定](methods.md) の §8-9）。
- [ ] **小さな差を主張する前に、パネルを替えて反復したか。** 同じ条件でも、パネルを替えると計数 `k` が
  大きく変動します（実測は[方法・共通設定](methods.md) の §8-9）。
- [ ] **計数 `k` を参照集合をまたいで比較していないか。** `k` は `M` で変わるため、p 値か
  share（`k / (n / (M + 1))`）を使ってください（[方法・共通設定](methods.md) の §8-6）。
- [ ] **判定は null 分布の 2 つの検定（計数検定と最大値検定）で行ったか。** 定義は
  [方法・共通設定](methods.md) の §8-5、使える条件は同 §8-3 と §8-7 です。
  q 値を使えるのは検定する遺伝子を絞った場合だけです。z 値も効果の大きさの記述にとどめ、判定には使いません。
  p >= 0.05 の条件では、上位遺伝子リストを「対象に固有の応答」として報告しません。
- [ ] **対照の水準（1 遺伝子の最大値）と null 分布（20 個以上の分布）を区別して書く。** 対照の水準は目安であり、
  偶然の範囲を表しません。順位を主張する根拠にする場合は null 分布を使ってください。
- [ ] **文献と食い違う結果も隠さず書く。** 今回、分泌性の炎症遺伝子（TNF、IL1B、C1q、S100A8/A9）では
  両方のモデルが文献と逆の向きを示しました。これは手法の限界として記録します。

### B-3. 文献を扱うときに守ること

- [ ] **PMID は「存在するか」だけでなく「主張と対応するか」まで確認する。** 実在する PMID でも、
  主張した遺伝子とは違う論文が割り当てられていた例が実際にありました。
- [ ] **証拠の第1層と第2層を分けて書く。** 第2層しかない場合は、そのことを明記します。
- [ ] **相反する一次文献は両方を引用する。** 都合のよい片方だけを選ばず、「相反（判定不能）」と書きます。
  たとえば補体 C3 には、欠損が保護的だという報告と、欠損がプラークを増やすという報告の両方があります。
- [ ] **判定が条件で変わる場合は、条件と感度まで書く。** たとえば TREM2 は、病期の早期と後期で
  逆の方向になります。本データが早期であることを明記して扱います。

## C. 技術とコードのときに守ること

### C-1. レポートを書くときに守ること

節の並べ方は[ISP レポートの標準構成](report_template.md)に従います。この章は、その構成の上で守る書き方の決まりです。

- [ ] **直近の分析の「狙い」と「考察」を具体的に書く。** 標準構成の「1. 背景」は数行に留め、
  プロジェクトの経緯を復唱しません。読み手が知りたいのは、今回何を確かめたかったのかです。
- [ ] **短く書くが、意味が伝わることを優先する。** 主語を省いた箇条書きや、記号で並べただけの要約は避けます。
  読み手は自分のメモの内側の事情を知りません。
- [ ] **自分だけに通じる言葉を使わない。** 初出の場所で説明するか、用語表を付けます。
- [ ] **用語表に、その解析で使う用語の定義を載せたか。** 少なくとも移動度、検出率、摂動できる細胞数、
  対照遺伝子、対照の水準、null 分布、z 値、p 値、q 値を載せます。定義の文は
  [方法・共通設定](methods.md) の §7 から取ります。新しい用語を作った場合は、[記述ルール](style-guide.md) の
  A-1 への追加は、`owners.md` か[競合の記録](conflicts.md)に記録します。
- [ ] **実測値と推定値を区別する。** 推定した値には「推定」と書きます。
- [ ] **英語と日本語の両方を用意したか。** ファイル名の付け方は[記述ルール](style-guide.md) B-6 にあります。
- [ ] **数値・図・表はスクリプトで再生成できるようにする。** 手作業で転記すると、
  その数字がどこから来たのか分からなくなります。

### C-2. リポジトリを扱うときに守ること

置き場所、成果物の扱い、認証情報の扱いは[記述ルール](style-guide.md) の B-5 にまとまっています。

- [ ] **push の前に `git fetch` する。** 他のエージェントが同時に push しているため、
  自分の変更を rebase してから push します。
- [ ] **規則を直したいときは、記録に残す。** 対象ページ、直したい点、提案、根拠、状態の 5 つを、受信箱ではなく `owners.md` か[競合の記録](conflicts.md)に書きます。
  5項目を書きます。commit メッセージに書くだけでは届きません。
- [ ] **文献照合の成果物をコミットしていないか。**
- [ ] **再利用するスクリプトは `templates/template_*.py` に置く。** ファイルの先頭に TEMPLATE（ひな形）と書き、
  埋め込まれている数値や判定が記入例であることを明示します。
- [ ] **置き場所を守る。** 解析スクリプトは `analysis/`、テンプレートは `templates/`、
  修正パッチは `patches/`、文書は `docs/` に置きます。
- [ ] **認証情報を残していないか。**
- [ ] **本体とマウス用のリポジトリを独立に管理したか。**
