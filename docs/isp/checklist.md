# ISP 遵守項目（チェックリスト）

この文書は、ISP（in silico perturbation、計算機上で遺伝子を1つ削除して細胞の状態変化を見る解析）を、
複数のエージェントと複数の PC で並行して進めるために守る項目をまとめたものです。
数値の基準は[合格基準](criteria.md)に、用語の定義は[用語と手法の定義](glossary.md)に書いてあります。
この文書は、その2つを前提にした「作業の決まりごと」です。

## 0. 最初に言葉の意味

読み進める前に、この文書で使う言葉を説明します。

- **Shift（シフト）**: 遺伝子を1つ削除したときに、細胞の状態が健常（WT）の状態へどれだけ近づいたかを表す値です。
  正の値なら「WT に近づいた」という意味になり、その遺伝子は病気を進めていると考えます。
- **符号が反転する**: 同じ遺伝子について、104M と 316M という2つのモデルが、正と負で逆の結論を出してしまうことです。
- **摂動できる細胞数**: その遺伝子を持っていて、実際に削除操作の対象になった細胞の数です。少ないと結果が安定しません。
- **検出率**: 対象の細胞のうち、その遺伝子を持っている細胞の割合です。低いと摂動できる細胞が少なくなります。
- **C4**: チームがあらかじめ決めた合格基準の1つで、「摂動できる細胞が 500 個以上あること」を指します。
- **系統マーカー**: CD8A や CD4 のように、その細胞が何の細胞であるかを決めている遺伝子です。
- **文献の証拠の第1層と第2層**: 第1層は自分で論文を取得して要旨を読んだもの、
  第2層は別のエージェントに調べさせて PMID だけを機械的に確認したものです。

## A. 解析を始める前に守ること

- [ ] **実行した条件を記録に残す。** 記録するのは、使ったモデル名、数値精度（fp32 か bf16 か）、
  1遺伝子あたりの細胞数の上限、比較した状態の組み合わせ、使った分類器の保存場所です。
  あとから条件が分からない結果は、誰も検証できないからです。
- [ ] **遺伝子ごとに「摂動できる細胞数」を数える。** 500 個に満たない遺伝子は C4 の不合格とし、
  除外したことを記録に書きます。今回のデータでは TREM2、SPP1、CCL2 などが該当しました。
- [ ] **陰性対照の遺伝子をリストに入れる。** ACTB や GAPDH のように、削除しても細胞の状態が変わらないはずの
  遺伝子です。これが動いたら、指標そのものを疑います。
- [ ] **出力フォルダは実行ごとに分ける。** 前の実行の結果を再利用すると、比較そのものが無意味になるからです。
- [ ] **基準を満たす前に規模を広げない。** 細胞数や遺伝子数を先に増やすと、失敗したときに原因が分からなくなります。

## B. 結果を解釈するときに守ること

- [ ] **1つのモデルだけで標的候補を報告しない。** 今回の測定では、モデルを替えると 55 遺伝子のうち
  18 遺伝子で符号が反転しました。つまり候補リストは、モデルの選び方で入れ替わります。
- [ ] **2つのモデルの結果が一致したことを「独立に再現した」と呼ばない。** 2つのモデルは同じトークン化と
  ランク符号化を共有しているため、発現量に由来する効果は両方で同じように現れます。
  独立した確認には、CRISPRi や Perturb-seq のような別の手法が必要です。
- [ ] **発現が少ない遺伝子の順位を解釈しない。** 検出率と摂動できた細胞数を必ず併記し、
  少ない場合は「判定不能」と書きます。
- [ ] **系統マーカーは標的候補にしない。** CD8A、CD4、CD19 などを削除すると、細胞の種類そのものが
  崩れる方向に結果が動くため、治療の標的として読むことはできません。
- [ ] **指標が何を測っているかを必ず添える。** 測っているのは「脾臓の免疫細胞が WT の状態にどれだけ近いか」
  であり、「病気そのものが良くなったか」ではありません。
- [ ] **文献と食い違う結果も隠さず書く。** 今回、分泌性の炎症遺伝子（TNF、IL1B、C1q、S100A8/A9）では
  両方のモデルが文献と逆の向きを示しました。これは手法の限界として記録します。

## C. 文献を扱うときに守ること

- [ ] **PMID は「存在するか」だけでなく「主張と対応するか」まで確認する。** 実在する PMID でも、
  主張した遺伝子とは違う論文が割り当てられていた例が実際にありました。
- [ ] **証拠の第1層と第2層を分けて書く。** 第2層しかない場合は、そのことを明記します。
- [ ] **相反する一次文献は両方を引用する。** 都合のよい片方だけを選ばず、「相反（判定不能）」と書きます。
  たとえば補体 C3 には、欠損が保護的だという報告と、欠損がプラークを増やすという報告の両方があります。
- [ ] **判定が条件で変わる場合は、条件と感度まで書く。** たとえば TREM2 は、病期の早期と後期で
  逆の方向になります。本データが早期であることを明記して扱います。

## D. レポートを書くときに守ること

節の並べ方は[ISP レポートの標準構成](report_template.md)に従います。この章は、その構成の上で守る書き方の決まりです。

- [ ] **直近の分析の「狙い」と「考察」を具体的に書く。** 標準構成の「1. 背景」は数行に留め、
  プロジェクトの経緯を復唱しません。読み手が知りたいのは、今回何を確かめたかったのかです。
- [ ] **短く書くが、意味が伝わることを優先する。** 主語を省いた箇条書きや、記号で並べただけの要約は避けます。
  読み手は自分のメモの内側の事情を知りません。
- [ ] **自分だけに通じる言葉を使わない。** 初出の場所で説明するか、用語表を付けます。
- [ ] **実測値と推定値を区別する。** 推定した値には「推定」と書きます。
- [ ] **英語と日本語の両方を用意する。** ファイル名は英語版を基本の名前にし、日本語版には「-jp」を付けます。
- [ ] **数値・図・表はスクリプトで再生成できるようにする。** 手作業で転記すると、
  その数字がどこから来たのか分からなくなります。

## E. リポジトリを扱うときに守ること

- [ ] **push の前に `git fetch` する。** 他のエージェントが同時に push しているため、
  自分の変更を rebase してから push します。
- [ ] **文献照合の成果物はコミットしない。** レポート（PDF・DOCX）、図、文献レコード、派生データは
  `.gitignore` で除外し、ローカルにのみ保管します。
- [ ] **再利用するスクリプトは `templates/template_*.py` に置く。** ファイルの先頭に TEMPLATE（ひな形）と書き、
  埋め込まれている数値や判定が記入例であることを明示します。
- [ ] **置き場所を守る。** 解析スクリプトは `analysis/`、テンプレートは `templates/`、
  修正パッチは `patches/`、文書は `docs/` に置きます。
- [ ] **認証情報を残さない。** トークンやワンタイムコードをチャットやファイルに書きません。
- [ ] **本体とマウス用のリポジトリは独立に管理する。** `petadimensionlab/Geneformer` と
  `petadimensionlab/Mouse-Geneformer-MPS` の間に相互参照を作りません。
