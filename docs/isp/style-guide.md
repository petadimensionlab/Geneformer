> # ⛔ 最初に必ずこのページを読んでください
>
> **ISP に関する作業、記述、レビューを始める前に、必ずこのページを読んでください。**
> 書き方、用語、表記、判定の語彙で迷ったときは、**このページが唯一の基準です**
> （各ページの書き方より、このページのルールを優先します）。
>
> - 判断に迷ったら、**推測で埋めずに「判定不能」と書いてください。**
> - 競合や重複の裁定の記録は [§E](#e-競合と裁定の記録について) にあります。

## 最優先の遵守項目（2026-09-17 追加）

**ミスはやむを得ませんが、結果の捏造につながる作為的な修正は絶対に行いません。**
この項目は、このページの他のどの規則よりも優先します。

1. **数値を変える処理を入れたら、値を変えていないことを実測で確かめてから報告します。**
   確かめ方の例: 実行条件（バッチサイズ、対象細胞の集合）を変えて、同じ値が出ることを確認します。
2. **辻褄合わせの処理を入れません。** 切り詰める、穴を埋める、例外を握り潰す、といった処理で
   「通る」ようにしません。**前提が崩れているときは、黙って通さず停止させます。**
3. **「実行が通ったこと」を「値が正しいこと」の根拠にしません。** 通ったかどうかと、測定が
   正しいかどうかは別です。通ったことを報告するときは、何を確かめたのかを添えます。
4. **誤りが見つかったら、訂正前と訂正後の数値を並べて報告します。** 自分の誤りを
   「都合の良い処理」と言い換えて軽く扱いません。誤りは誤りとして書きます。
5. **自分の誤りを記録に残します。** コミットメッセージには、何が欠陥で、何が変わったかを書きます。

> この項目は**派生リポジトリ（scPEFT など）にも適用します**。適用範囲は
> [§G 派生リポジトリへの適用](#g-派生リポジトリへの適用) を見てください。

# A. データ分析のルール

**解析結果を読み、解釈し、判定を書くときのルールです。**
数値の基準そのものは [評価基準](criteria.md) にあります。

## A-1. 分析の用語（これだけを使う）

**左の列を使い、右の列は使いません。** 初出では真ん中の列のように意味を一度だけ添えます。

| 使う表記 | 意味（初出で添える説明） | 使わない表記 |
|---|---|---|
| **ISP** | in silico perturbation の略。計算機上で遺伝子を操作する解析 | in-silico（ハイフン付き） |
| **Shift（Shift_to_goal_end）** | 遺伝子を削除したとき、細胞の状態が goal（例: 健常）へどれだけ近づいたかを表す値。**常に指数表記で書く**（[C-2](#c-2-数値の表記)） | シフト、シフト量 |
| **削除** | 遺伝子を 1 つ取り除く操作。この Wiki の基本操作 | KO（データ列名を除く）。実験操作の説明として「ノックアウト」は可 |
| **摂動できる細胞数** | その遺伝子のトークンを持ち、実際に削除の対象になった細胞の数 | 摂動対象細胞数、削除できる細胞数 |
| **検出率** | 対象の細胞のうち、その遺伝子を持っている細胞の割合 | 発現率 |
| **遺伝子リスト** | 解析対象として選んだ遺伝子の集合 | 遺伝子パネル、遺伝子セット |
| **細胞プール** | 対象にする細胞型の集合。初出以降は「プール」と省略可 | 細胞集団、セルプール |
| **状態対** | 比較する 2 つの状態の組（`start_state` と `goal_state`） | state pair、状態ペア |
| **状態分離** | 埋め込み空間での 2 状態の隔たり | separation、分離度 |
| **相対距離** | 距離 ÷ 2 つのベクトルの平均ノルム | 分離率、relative distance |
| **ノイズ床（2.1e-04）** | 計算誤差だけで符号が反転しうる `Shift` の大きさ | 閾値、しきい値 |
| **符号が反転する**（名詞は「符号の反転」） | 同じ遺伝子で、2 つの条件（モデル、組織、時点）の `Shift` の正負が食い違うこと | 符号が逆、符号反転 |
| **健常（WT）** | 比較の基準になる非疾患側 | 正常、コントロール（本文では使わない） |
| **疾患（AD、PD）** | アルツハイマー病（AD）、パーキンソン病（PD）。初出では日本語名を添える | 病態（文脈が不明確なとき） |
| **移動度** | 埋め込みベクトルがどれだけ動いたか。**`Shift` の別名として使わない**（定義は [方法・共通設定](methods.md) §7） | 動き、変化量 |
| **対照遺伝子** | 対象と同じ細胞で同じ操作を行う遺伝子（選び方は [方法・共通設定](methods.md) §7-1） | コントロール遺伝子、陰性対照 |
| **対照の水準** | 対照遺伝子を操作したときの移動度の最大値（定義は同 §7） | 対照値、ベースライン |
| **null 分布** | 順位位置を対象に合わせた遺伝子の移動度の分布。偶然の範囲を決める基準（定義と数式は同 §8） | ヌル分布、帰無分布 |
| **null 遺伝子** | null 分布を作るために選ぶ、生物学的に無関係と考えられる遺伝子（選び方は同 §8） | 陰性対照遺伝子 |
| **z 値** | 移動度が null の平均から標準偏差いくつ分離れているか。**記述にだけ使い、判定には使わない**（同 §8） | 標準化得点 |
| **p 値** | その値以上に動く遺伝子が偶然出る確率。片側で数える（同 §8） | 有意確率 |
| **q 値** | p 値を Benjamini–Hochberg 法で補正した偽発見率（同 §8-3） | 補正 p 値、FDR |
| **計数（`k`）** | 対象と null 遺伝子を合わせた値のうち、その遺伝子が最大になる数（同 §7） | カウント、順位 |
| **share** | 計数を、同程度の遺伝子で期待される値で割った値（同 §7、§8） | 規格化計数、比 |

**意味の本文はここに書きません。** この表は**使う語と使わない語を決める**ためのもので、
定義と数式の正典は [方法と共通設定](methods.md) §7〜§9 です（[執筆者名簿](owners.md) §4）。

## A-2. 根拠の種類（A、B、C）

**数値には根拠の種類を必ず添えます。** 根拠のない数値は書きません。

| 種類 | 意味 | 扱い |
|---|---|---|
| **A** | 自分たちの実測（自データ、または同一リポジトリの実行） | **合否の線に使える** |
| **B** | 他組織・他データからの借用 | 条件が違うため**要確認**と明記する |
| **C** | 未確立（決めるための測定をしていない） | **合否に使ってはいけない**。確立方法を示す |

- **合否の線に使えるのは A だけです。** C の基準で判定した場合は「暫定」と明記します。
- **実測には条件を添えます。** モデル、組織、細胞数、遺伝子数、数値精度を書きます。
  条件のない数値は引用しません。出所はファイル名か実行名で示します
  （例: `docs/quantization/REPORT-316M-ISP-jp.md`、実行名 `isp-316m-bf16-full`）。

## A-3. 判定の語彙（2 つだけ）

**合否の語（合格・不合格）は使いません。** 基準を満たしたかどうかは、
**測った値と基準の値を併記**して、読み手が自分で判断できるように書きます。

| 語 | いつ使うか |
|---|---|
| **未検証** | その基準を確かめる実行をしていない |
| **判定不能** | 測ったが、データでは決められない |

個々の数値が未測定のときは「要測定」と書きます。

**書き方の例**: 「DMNX_Neu の上位 16 遺伝子の最大は 2.13e-03、null 15 遺伝子の 95 パーセンタイルは 1.34e-03」
（値と基準を並べる。`不合格` とは書きません）。

> **どの基準をどの解析に適用するかは、解析を始める前に合意します。**
> 事後に基準を当てはめて判定を出すことはしません。

## A-4. 基準と目安

- **[評価基準](criteria.md) の E1〜E6**（旧称は C1〜C6）が「観点」です。
- **「基準」と「目安」を区別します。** 目安は実測例の間を取った線であり、**合否には使いません**。
  解釈を控える判断にだけ使います。

## A-5. 主張してよい範囲

- **基準と比べるときは、値と基準を併記します。** 判定の語（合格・不合格）は使いません（[A-3](#a-3-判定の語彙2-つだけ)）。
  根拠の種類が A でない基準は、比較には使えても結論の根拠にはなりません。
- **順位を主張する前に null 比較を行います。** null 分布が無い段階では、
  「上位の遺伝子」を介入候補として報告しません。
- **差があることを「ノイズの証拠」とは書きません。** 異なる条件間の差は、
  一致を期待する前提が正当化されていない限り、何も証明しません。
- **推定値には「推定」と書き、根拠を添えます。** 実測と推定を混ぜません。
- **方法上の制約がある数値からは結論を出しません。** 例: 別の細胞プールで作った null を使って
  計算した割合から、そのプールの性質を述べません。**測った対象と、結論を述べる対象が同じかを確かめます。**

## A-6. 必ず併記する条件

解析の数値を書くときは、次の条件を併記します。どれか欠けると読み手が検証できません。

| 項目 | 例 |
|---|---|
| モデル | V2-316M |
| 数値精度 | bf16 |
| 摂動できる細胞数の上限 | `max_ncells=300` |
| 実際に摂動できた細胞数 | 遺伝子ごとに記録 |
| 状態対 | Parkinson disease → normal |
| 細胞プール | DMNX_Neu、GPI_Neu |
| モデルの学習レジーム | 1 エポックの 31% など |

# B. 技術・コード保守のルール

**コードを書き、パッチを当て、リポジトリを操作するときのルールです。**

## B-1. 技術の用語

| 使う表記 | 意味（初出で添える説明） | 使わない表記 |
|---|---|---|
| **モデル（V2-104M、V2-316M）** | Geneformer の事前学習済みモデル。数字はパラメータ数を表す | 104M、316M（初出前の単独使用） |
| **数値精度（fp32、bf16）** | 計算に使う浮動小数点の形式 | dtype だけでの言及 |
| **分類器（CellClassifier）** | 細胞型を判定するために追加学習したモデル | ヘッド、probe |
| **微調整（fine-tuning）** | 分類器を目的のタスクに追加学習すること | fine-tune、ファインチューン（日本語の文では使わない） |
| **細胞型** | 単球や T 細胞といった区別。データの列名は `celltype` のまま | 細胞集団、細胞種 |

## B-2. 言語

| 対象 | 規則 |
|---|---|
| 本文（説明文） | 日本語です。 |
| コード識別子、ファイル名、ディレクトリ名 | 英語のまま書きます（`Shift_to_goal_end`、`max_ncells`）。日本語に置き換えるとコードと本文が対応しなくなります。 |
| 指標名、関数名、パラメータ名 | 英語のまま書きます。初出で日本語の説明を一度だけ添えます。 |
| コミットメッセージ | 英語で書きます（1 行目に種別と要約、本文に理由）。**書いた人の呼び名**（例: `AG-GH`）を書き入れます。 |

## B-3. 置き場所

| 種類 | 置き場所 |
|---|---|
| 解析スクリプト | `analysis/` |
| 修正パッチ | `patches/` |
| 再利用する雛形 | `templates/template_*.py`（先頭に TEMPLATE と書き、埋め込んだ数値が記入例であることを明示） |

| 生データ・結果の出力 | `input/`（`.gitignore` の対象。コミットしません） |

## B-4. パッチと再適用

- **`./patches/apply_patches.sh` を実行してから解析を始めます。** device、bf16、チェックポイントの修正をまとめて適用します。
- **`./download.sh` を実行したら、必ず再適用します。** `geneformer/*.py` を取り直すため、ローカルのパッチが外れます。
- **長時間の微調整はステップ単位チェックポイントを有効にします**（`patches/checkpoints/`）。中断で全損しないためです。
- **依存関係のバージョンは [再現手順](how_to_run.md) に従います**（`perturb_data` のハングを避けるための固定を含みます）。

## B-5. リポジトリ操作

1. **編集の前に `git fetch` をします。** 先に進んでいる変更がある場合が多いためです。
2. **編集は 1 名（AG-GH）が行います。** 担当は [執筆者名簿とページ担当](owners.md) §2 にあります。
   - **分担は廃止しました（2026-09-25）。** 以前は担当外のページへの依頼を
     [受信箱](requests/README.md)（`docs/isp/requests/<呼び名>.md`）に追記していましたが、
     編集を 1 名に集約したため、この仕組みは使いません。**`requests/` は履歴として残し、追記しません。**
   - 分担が無いため、**どのページも直接直してかまいません**（「担当外」という状態がありません）。
   - 編集を他者に任せたい場合は、commit メッセージではなく [執筆者名簿](owners.md) に書き残します。
3. **push が拒否されたら、取り込んでから push し直します。** 競合が出た場合は [競合の記録](conflicts.md) の方針に従います。
4. **認証情報を残しません。** トークンやワンタイムコードをチャットやファイルに書きません。
5. **本体とマウス用のリポジトリは独立に管理します。** `petadimensionlab/Geneformer` と
   `petadimensionlab/Mouse-Geneformer-MPS` の間に相互参照を作りません。
6. **取り込んだ後に、競合マーカーが残っていないか確認します。**
   `git pull --rebase --autostash` は、stash の適用が競合したまま**コミットまで進むことがあります**。
   実例: `38337b5` が `<<<<<<< Updated upstream` を `requests/AG-GB10.md` に持ち込み、main に残りました。
   **取り込みの後に `grep -rn "^<<<<<<<" docs/` を実行し、0 件を確認してから作業を続けます。**
   マーカーを見つけたら、**入れた本人が直します**（どのページでもかまいません）。
7. **文献照合の成果物はコミットしません。** レポート（PDF・DOCX）、図、文献レコードは
   `.gitignore` で除外し、ローカルにのみ保管します。

**レポート（DOCX、PDF）の書き方**

- 節立ては [レポートの標準構成](report_template.md) に従います。
- 冒頭の要約は 5 行以内にまとめ、**目的と結論を先に**書きます。プロジェクトの経緯は書きません。
- 用語表を必ず付けます。
- 日本語版と英語版を作ります。ファイル名は英語を基本とし、日本語版には「-jp」を付けます。
- 数値、図、表はテンプレートのスクリプトで再生成できる状態にします。

**各ページの骨格**

1. **目的**: そのページは何のためにあるかを 1 段落で書きます。
2. **前提**: 対象データ、モデル、条件（組織、時点、細胞数、数値精度）を書きます。
3. **本文**: 結果、解釈、限界を書きます。
4. **出所**: 数値と引用の出典を書きます。

# C. 共通（表現と表記）

**どちらの作業でも守るルールです。**

## C-1. 表現

1. **一文で一つのことを書く。** 接続詞で 2 つ以上の主張をつながない。
2. **主語と述語を省略しない。** 「〜を記録」ではなく「〜を記録します」と書く。
3. **記号で語句を並べない。** 「A／B／C」ではなく、読点でつなぐか箇条書きを分ける。
4. **略語は初出で意味を添える。** 例: ISP（in silico perturbation、計算機上での遺伝子操作）。
5. **記号だけの要約を書かない。** 情報を詰め込むときは表にする。
6. **同じものは同じ語で呼ぶ。** 本文と表で別名を使わない。
7. **実測と推定を分ける。** 推定には「推定」と書き、根拠を添える（[A-5](#a-5-主張してよい範囲)）。
8. **数値には出所を添える。** 出所が分からない数値は書かない。未測定なら「要測定」と書く。
9. **表の下に注を 1 つ置く。** 読み方と条件を説明する。
10. **ページ間の参照はリンクにする。** 「§2 を参照」だけでは読めないため、リンクと節名を添える。
11. **文体は「です・ます」調で統一する。** 手順の指示は「〜してください」と書く。
12. **見出しは名詞句で短くする。** 節の 1 行目で、その節が何を述べるかを書きます。
13. **定着した略称は使ってよいが、自分で作った短縮語や記号は使わない。**
    使ってよい例は `cDC1_CLEC9A`、`Mφ_MARCO`、T/NK、MPS、Geneformer、`cls_and_gene` などの識別子です。
    使わない例は `top20`、`n=`、`ρ` です。
14. **前の値と比べるときは、変化の向きを書く。** 「増えました」「減りました」「変わりません」と書き、
    **「〜のまま」は変化が無いときだけ使います**（増えているのに「のまま」と書くと事実と逆になります）。

## C-2. 数値の表記

| 対象 | 規則 | 例 |
|---|---|---|
| 移動度、null の値 | **0.01 以上は小数 3 桁、0.01 未満は指数表記で有効数字 3 桁** | `0.113`、`4.80e-03` |
| 小さい値（`Shift`、相対距離） | **常に指数表記**で有効数字 3 桁 | `5.21e-05`（`0.0000521` とは書きません） |
| パーセント | 小数 1 桁 | `8.3%` |
| 基準の値 | 指数表記 | `> 2.1e-04` |
| ファイルパス、コマンド、識別子 | バッククォートで囲みます | `` `docs/isp/criteria.md` `` |
| 細胞数、遺伝子数 | 3 桁ごとに区切ります | `4,126` |

**割合や比は、分子と分母を添えて書きます。** 例は「2,394 個のうち 0 個」「上位 20 個のうち 19 個」です。
`0/2,394` や `19/20` は使いません（同じ数字が別の量に現れ、読み手が写し間違いと読むため）。

## C-3. `WT` と `Control` は同じ状態です

データの `Diagnosis` 列の値は `AD` と `Control` ですが、ISP の `goal_state` は `WT` です。
初出で「対照（データ上は `Control`、ISP 上は `WT`）」と一度だけ明記し、以降は文脈で統一します。
