# ISP ドキュメント共通規約（3 名のエージェント共通）

> **この文書が用語・表記・評価の書き方の唯一の基準です。**
> 各ドキュメント（criteria / glossary / report_template / results / methods / pd_atlas / 各臓器ページ）は
> ここに従ってください。矛盾を見つけたら、この文書を直してから他を直します。
>
> 作成の背景: 複数のエージェントが並行して書き足したため、
> 同じ概念が「`Shift_to_goal_end`」と「移動度」、「Microglia」と「MG」と「ミクログリア」のように
> ばらばらに表記されていました。読み手が同じものだと気づけない状態を解消するための規約です。

---

## 1. 言語

| 対象 | 規則 |
|---|---|
| 本文（説明文） | **日本語** |
| コード識別子・ファイル名・ディレクトリ名 | **英語のまま**（`Shift_to_goal_end`, `max_ncells`, `cell_states_to_model`） |
| 指標名・関数名・パラメータ名 | **英語のまま**。初出時に日本語の説明を丸括弧で添える |
| コミットメッセージ | **英語**（1 行目に種別＋要約、本文に理由） |
| 新規ドキュメント | 日本語ファイルは `*-ja.md` を付けない（`docs/isp/` 配下は日本語が既定）。英語版を作る場合のみ `.en.md` |

**本文で英語の識別子を日本語に置き換えないこと。** 置き換えるとコードと本文が対応しなくなります。
例: `Shift_to_goal_end` を本文で「移動度」と呼ぶのは**禁止**（一時期そう書いて混在しました）。

| 概念 | 本文での書き方（初出時） | 以降の書き方 | コード上の名前 |
|---|---|---|---|
| 手法 | in silico perturbation（ISP） | ISP | `InSilicoPerturber` |
| 主指標 | `Shift_to_goal_end`（削除により細胞集団が goal 側へどれだけ動いたかを表す値） | `Shift_to_goal_end` | `Shift_to_goal_end` |

| 1 回の摂動に使う細胞数の上限 | `max_ncells` | `max_ncells` | `max_ncells` |

| 遺伝子の並び | トークン列（長さは最大 4,096） | トークン列 | `input_ids` |
| 細胞を表す数値ベクトル | 埋め込みベクトル | 埋め込み | `cell_emb` / CLS |

### 注意: `WT` と `Control` は同じものを指す

データの `Diagnosis` 列は `AD` / `Control` ですが、ISP の `goal_state` は `WT` です。
**本文では「対照（データ上は Control、ISP 上は WT）」と初出で一度だけ明記**し、以降は文脈で統一します。

## 3. 表記ルール

| 対象 | 規則 | 例 |
|---|---|---|
| 小さい値 | 指数表記、有効数字 3 桁 | `5.21e-05`（`0.0000521` と書かない） |
| パーセント | 小数 1 桁 | `8.3%` |
| 閾値・基準 | 指数表記で統一 | `> 2.1e-04` |
| ファイルパス・コマンド・識別子 | バッククォート | `` `docs/isp/criteria.md` `` |
| 細胞数・遺伝子数 | 3 桁区切り | `4,126` |
| 実験名 | `<disease>_<tissue>` の小文字 | `ad_rosmap`, `ad_spleen` |

## 4. 評価の書き方（最重要）

**評価には必ず「観点」と「基準」を対で書き、基準の根拠の種類を明示する。**

| 根拠の種類 | 意味 | 扱い |
|---|---|---|
| **A. 実測** | 自データまたは同一リポジトリで測った値 | そのまま基準に使える |
| **B. 借用** | 別組織・別条件の実測値 | **要確認**と明記する |
| **C. 未確立** | 決めるための測定をしていない | **判定に使わない**。確立方法を示す。判定は「暫定」と書く |

表の形:

| 観点（何を評価するか） | 基準 | 根拠 | 実測 | 判定 |
|---|---|---|---|---|
| 信号の大きさ | null 分布の 95 パーセンタイル超え | C 未確立 | — | 保留 |
| 符号の安定性 | > 2.1e-04 | A 実測 | 最大 1.64e-04 | 不合格 |

- 判定は **合格／不合格／保留／未実施** のいずれかで書く
- **基準を示さない評価を書かない**
- **根拠のない閾値を置かない**（丸い数字を思いつきで置くのは禁止。置くなら C と明記して確立方法を書く）

## 5. ドキュメントの役割分担

| 文書 | 役割 | 重複させない内容 |
|---|---|---|
| **`CONVENTIONS.md`（本文書）** | 用語・表記・評価の書き方の**唯一の基準** | — |
| `criteria.md` | 何をもって成功とするか（基準の一覧と根拠） | 用語の定義は書かない（本文書を参照） |
| `glossary.md` | 概念の説明（トークン化・埋め込み・指標の式） | 基準の一覧は書かない（criteria.md を参照） |
| `report_template.md` | レポートの構成 | 用語・基準は書かない（参照する） |
| `methods.md` / `results.md` / 各臓器ページ | 実行条件と結果 | 用語の再定義をしない |

**同じ定義を 2 か所に書かない**（片方だけ更新されて矛盾するため）。

## 6. 出力先とファイル命名（既存規則の再掲）

```
input/<TISSUE>/results/isp/<experiment>/
    <experiment>_early_isp_stats_combined.csv   # 全遺伝子の結果
    isp_state_embs*.pkl                         # 状態埋め込み（共有）
    <Gene>/isp_stats.csv                        # 遺伝子ごとの結果
```

`<experiment>` は `<disease>_<tissue>` の小文字（`ad_spleen`, `ad_rosmap`）。

## 7. 書き足すときの手順

1. 用語は本文書の表から選ぶ。表にない概念を導入するときは、**先に本文書へ追記**してから使う
2. 数値は §3 の表記で書く
3. 評価を書くときは §4 の表を使う
4. 実行条件を変えた場合は、**変更前 / 変更後 / 理由 / 影響**を必ずセットで書く
5. 矛盾を見つけたら、**本文書を先に直し**、他の文書を合わせる
