## 3. 担当外の依頼は受信箱に残す（鉄則）

**担当外のページを直したいときは、直接書き換えず、相手の受信箱にメモとして残します。**
commit メッセージに書くだけでは届きません。メッセージは流れて消えるためです。**依頼が確実に届くことが、分担を成立させる条件です。**

| 操作 | できる人 |
|---|---|
| 相手の受信箱に**追記**する | 誰でも可（担当ページの規則の唯一の例外） |
| 受信箱の行を**書き換え・削除**する | その受信箱の持ち主だけ |
| 担当ページを直接編集する | そのページの主担当だけ |

**メモに必ず書く項目**は、対象ページ、直したい点、提案、根拠、状態の5つです。根拠には実測値かファイル名を書きます。

**主担当の義務は2つです。**

1. **作業を始める前に、自分の受信箱（`docs/isp/requests/<自分の呼び名>.md`）を確認します。**
2. **対応したら、その行の状態を「対応済み（コミット番号）」に更新します。** 対応しない場合は、理由を追記します。行は消しません。

受信箱の置き場所と書き方は[受信箱の説明](requests/README.md)にあります。

## 4. 規則の置き場所

**規則の本文はこのページに置きません。** 同じ内容を 2 か所に書くと、片方だけが直されて食い違います。
実際にその食い違いが起きた記録は[競合の記録](conflicts.md)にあります。内容ごとに正典を 1 つ決め、他のページは参照だけを書きます。

| 内容 | 正典 |
|---|---|
| 用語、表記、根拠の種類、判定の語彙、主張してよい範囲、必ず併記する条件 | [記述ルール](style-guide.md) A 章 |
| 数値の基準（E1〜E6）と、その根拠 | [評価基準](criteria.md) |
| 作業の前に確認する項目、判定の手順 | [遵守項目](checklist.md) |
| 手法と統計量の定義、null 分布の数式 | [方法・共通設定](methods.md) §7〜§9 |
| 用語の一般的な定義（ISP、Shift、ノイズ床など） | [用語と手法の定義](glossary.md) |
| リポジトリ操作（fetch、push、commit、成果物の扱い） | [記述ルール](style-guide.md) B-5 |
| 競合の経緯と裁定 | [競合の記録](conflicts.md) |
| 誰がどのページを担当するか、依頼の出し方 | このページ（§2、§3） |

## 6. 共有のしかた

このページを編集したら、[索引（README）](README.md)のページ一覧から辿れるようにしておきます。
他の執筆者は `git pull` でこのページを読み、担当と受信箱を確認してください。
担当を変える場合は、変更の理由を添えてこのページを直してください。
