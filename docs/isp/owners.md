# 執筆者名簿とページ担当

このページは、同じ Wiki を複数のエージェントが同時に編集して競合が繰り返されたため、**誰が何を書くか**と**担当外の依頼をどう届けるか**を決めたものです。
規則の正典は §4 の表に、これまでの競合は[競合の記録](conflicts.md)にあります。
記述ルールは **A（データ分析）、B（技術とコード保守）、C（共通の表現と表記）** の3部構成です。

## 3. 担当は AG-GH 1 名（2026-09-25 に一本化し、受信箱は廃止）

**2026-09-25 の Nakaoka さんの指示（「受信箱とか止めて、最終的に 1 名に全部任せて AG-GH に」）により、
全ページの主担当を AG-GH 1 名にしました。分担が無くなったため、受信箱（`docs/isp/requests/`）は廃止します。**

- 規則の本文、ページの編集、裁定の記録は、すべて **AG-GH** が行います。
- 他のマシン（AG-GB10、AG-MAC）は規則の編集を行いません。直したい点は、commit メッセージや受信箱ではなく、
  **このページか[競合の記録](conflicts.md)に記録**してください。
- `docs/isp/requests/` の各ファイルは**過去の記録として残します**（新しい追記はしません）。
  2026-09-25 の時点で未対応だった依頼は、**AG-GH の作業**として扱います。

**廃止した仕組みで行っていたこと（参考）**: 分担していた当時は、「担当外のページを直したいときは直接書き換えず、
相手の受信箱にメモとして残す」を鉄則とし、メモには対象ページ・直したい点・提案・根拠・状態の 5 つを書いていました。
分担が無くなったため、この手順は不要になりました。

**受信箱に触れている記述が残っているページ（AG-GH が直します）**: `style-guide.md` の 51・214〜218・225・228・350・388 行。

## 4. 規則の置き場所

**規則の本文はこのページに置きません。** 同じ内容を 2 か所に書くと、片方だけが直されて食い違います。
実際にその食い違いが起きた記録は[競合の記録](conflicts.md)にあります。内容ごとに正典を 1 つ決め、他のページは参照だけを書きます。

| 内容 | 正典 |
|---|---|
| 用語、表記、根拠の種類、判定の語彙、主張してよい範囲、必ず併記する条件 | [記述ルール](style-guide.md) A 章 |
| 数値の基準（E1〜E6）と、その根拠 | [評価基準](criteria.md) |
| 作業の前に確認する項目、判定の手順 | [遵守項目](checklist.md) |
| 手法と統計量の定義、null 分布の数式 | [方法・共通設定](methods.md) §7〜§9 |
| 用語の一般的な定義（ISP、Shift、ノイズ床など） | [用語と手法の定義](glossary.md) |
| リポジトリ操作（fetch、push、commit、成果物の扱い） | [記述ルール](style-guide.md) B-5 |
| 競合の経緯と裁定 | [競合の記録](conflicts.md) |
| 視覚設計（レイアウト、文字サイズ、色、余白、内容の密度、階層） | [図表・スライド・ポスターの視覚設計ルール](design.md) |
| 実行の手順（再現方法） | [再現手順](how_to_run.md) |
| レポートの節立てと体裁 | [レポートの標準構成](report_template.md) |
| 文献のセクション別要約（GSE174367） | [Morabito 2021](ad_morabito2021.md) |
| 誰がどのページを担当するか、依頼の出し方 | このページ（§2、§3） |

## 5. 共有のしかた

このページを編集したら、[索引（README）](README.md)のページ一覧から辿れるようにしておきます。
他の執筆者は `git pull` でこのページを読み、担当（AG-GH）を確認してください。
担当を変える場合は、変更の理由を添えてこのページを直してください。
