# ISP の合格基準（解析を始める前に合意する項目）

> **この文書の目的**: ISP（in silico perturbation）を走らせる前に、
> **「何をもって成功とするか」「どんな条件なら結果を報告してよいか」** を先に決めておくこと。
> 基準が無いまま走らせると、**ノイズ域の値を解析結果として扱ってしまう**事故が起きます
> （実際に起きた。§5 の事例を参照）。

---

## 0. 何を求めているか

「疾患状態の細胞から遺伝子 X を 1 つ削除したとき、その細胞集団が健常（goal）方向へ
どれだけ戻るか」を遺伝子ごとに測り、**介入ターゲット候補を順位づけする**こと。

必要なのは値の大きさそのものではなく、
**順位が安定して意味を持つこと**（ノイズに埋もれていないこと）。
`Shift_to_goal_end` は元々 1e-4〜1e-3 の桁にしかならない指標なので、
「大きいかどうか」ではなく「ばらついているか」で判断します。

---

## 1. 合格基準（数値で定義）

| # | 観点（何を評価するか） | 基準（合格ライン） | なぜその基準か |
|---|---|---|---|
| **C1** | 信号の大きさ | 少なくとも一部の遺伝子で \|Shift\| > **2.1e-04** | この値を下回ると fp32↔bf16 で符号が反転する（実測） |
| **C2** | 順位の作れやすさ（遺伝子間の差） | Shift の四分位範囲（IQR） > **4.2e-04** | 参照実測の IQR は約 1.0e-03。散らばりゼロでは順位が作れない |
| **C3** | 指標そのものの妥当性 | 陰性対照（ACTB・GAPDH）の \|Shift\| < **2.1e-04** | 動かないはずの遺伝子が動けば、指標の解釈が崩れる |
| **C4** | 遺伝子ごとの測定可能性 | 摂動対象細胞 **≥ 500**（暫定） | 241 細胞で値が完全に 0 に潰れた（TREM2）。SORL1 は 2,281 細胞で測定可 |
| **C5** | 状態の識別性（実行前の前提） | 埋め込み空間での相対距離 **≥ 15%**（暫定） | 8.27% の状態対で信号が出なかった。発現量での差は 20.3% |
| **C6** | 再現性 | C1 を満たす遺伝子について fp32 と bf16 で符号一致 | 1e-4 の桁では精度差で 20〜70% 変動する（実測） |

**C1〜C3 を満たさない実行結果は、「解析結果」として報告してはいけない**（＝ノイズ域）。
**C4・C5 は実行前に満たしておくべき前提条件**で、後から救えない。

---

## 2. 実行前チェックリスト

- [ ] **C5**: 対象状態対の分離を測ったか（埋め込み空間で相対距離 ≥ 15%）。未達なら状態対を変える
- [ ] **C4**: 摂動対象遺伝子それぞれの「そのトークンを持つ細胞数」を数えたか。500 未満は除外と明記する
- [ ] **C3**: 陰性対照（ACTB・GAPDH など）を遺伝子リストに入れたか
- [ ] **陽性対照**は「対象細胞で実際に発現している」遺伝子から選んだか（発現 0 の遺伝子を陽性対照にすると意味がない）
- [ ] `max_ncells` は対象細胞数をカバーしているか（例: 4,126 細胞あるのに 1,000 では 24%）
- [ ] トークン長を切り詰めていないか（切り詰めるなら、細胞型ごとの喪失トークン率を記録する）
- [ ] `datasets==4.0.0` か（5.x は `perturb_data` がハング）
- [ ] 長時間の fine-tune は**ステップ単位チェックポイント**を有効にしたか（`patches/checkpoints/`）
- [ ] **`./patches/apply_patches.sh` を実行したか**（device / bf16 / checkpoints をまとめて適用。`download.sh` はローカルパッチを上書きするため、ダウンロード直後は必ず実行する）

---

## 3. 実行後に必ず記録する項目

| 項目 | 例 |
|---|---|
| 実行条件 | トークン長 / max_ncells / 状態対 / モデル / dtype / 分類器チェックポイントのパス |
| 遺伝子ごと | **摂動対象細胞数**、`Shift_to_goal_end` |
| 分布 | 平均・中央値・IQR・最小・最大 |
| 陰性対照の値 | ACTB、GAPDH |
| 判定 | C1〜C6 のどれを満たし、どれを満たさないか（理由付き） |

**摂動対象細胞数は必ず併記する**こと。これが無いと C4 の判定ができない。

---

## 4. 手順（規模を広げる順序）

1. **対象細胞で成立するか確認する**（少数の、発現率が高く分離の大きい状態対で）
   — C1〜C3 を満たすか
2. 満たした場合のみ**遺伝子を増やす**（C4 判定を併記）
3. それでも足りなければ**細胞数を増やす / 状態対を変える / 細胞型を追加する**
4. 満たさないまま規模を広げない（失敗の原因が切り分けられなくなる）

## 5. 実際に起きた失敗（再発防止のための記録）

対象: GSE174367（ROSMAP 前頭前皮質 snRNA-seq, Morabito 2021）× Geneformer V2-316M、ミクログリア。

### 5-1. 8 遺伝子すべてがノイズ床以下、しかも分散ゼロ

| 遺伝子 | Shift_to_goal_end |
|---|---|
| APOE | −5.21e-05 |
| TREM2 | −1.64e-04 |
| TYROBP | −3.57e-05 |
| BIN1 | −1.0e-04 |
| CD33 / ABCA7 | ±0.0 |

→ **C1・C2 不合格**。

### 5-2. 摂動できた細胞が少なすぎた（C4 違反）

ミクログリア 4,126 個のうち、AD 側でそのトークンを持つ細胞数:

| 遺伝子 | 細胞数 | 割合 |
|---|---|---|
| TREM2 | 241 | 8.8% |
| ABCA7 | 216 | 7.9% |
| CD33 | 284 | 10.4% |
| APOE | 966 | 35.2% |
| BIN1 | 1,418 | 51.7% |
| SORL1 | 2,281 | 83.2% |
| INPP5D | 2,350 | 85.7% |
| **SPI1** | **0** | 0%（発現なし＝陽性対照の選定ミス） |

### 5-3. 状態分離が埋め込み空間で圧縮されていた（C5 違反）

| 空間 | AD vs 対照の相対距離 |
|---|---|
| 発現量（pseudobulk） | **20.3%** |
| ISP が使う埋め込み | **8.27%**（cos 0.9966） |

分類器を「細胞の種類」で fine-tune しているため、埋め込みは細胞型を強く表し、
同一細胞型内の疾患差は相対的に小さくなる。参考として MG1 vs MG2 の発現差は 28.4%。

### 5-4. 速度優先で削った前提（すべて影響が実測されている）

| 項目 | 本来 | 削った設定 | 実測影響 |
|---|---|---|---|
| トークン長 | 4,096 | 3,072 | 全体の 7.2% 喪失（EX 21.3%、INH 16.6%、MG 0.3%） |
| 学習細胞数 | 2,000/種類 | 1,000/種類 | 学習量が半減 |
| 摂動の細胞数 | — | 1,000（MG の 24%） | C4 違反 |
| 状態対 | — | AD vs 対照（8.27%） | C5 違反 |

### 5-5. ノイズ床は実測でも確認できた（bf16 と fp32 の差）

同じ条件・同じ状態対で、計算精度だけを変えて 3 遺伝子を測定（出力先を分け、キャッシュを排除して実行）:

| 遺伝子 | bf16 | fp32 | 相対差 | 符号 |
|---|---|---|---|---|
| APOE | −5.21e-05 | −8.76e-05 | **68.2%** | 一致 |
| SORL1 | −1.14e-04 | −8.85e-05 | 22.2% | 一致 |
| TREM2 | −1.64e-04 | −1.11e-04 | 32.7% | 一致 |

状態埋め込み自体の差は cos 0.99999 / 相対差 0.5%。

**この桁（1e-4 前後）では、計算精度を変えるだけで値が 20〜70% 変動する。**
今回の 3 遺伝子は符号が一致したが、変動幅が値そのものと同程度であり、
**この水準での順位づけは意味を持たない**。C1（信号がノイズ床を超えること）の必要性が
自データでも裏づけられた。

### 5-6. 運用上の失敗

| 事象 | 原因 | 対策 |
|---|---|---|
| 7 時間分の学習を喪失 | `save_strategy="epoch"` のハードコード＋自動化が失敗と誤判定して `rm -rf` | `patches/checkpoints/` でステップ単位保存と自動再開を実装 |
| bf16 の ISP が即落ち | `download.sh` がローカルパッチを上書き | `patches/bf16/` を再適用（README に明記） |
| ノイズ域の結果を報告 | 合格基準が無かった | **本文書** |
| fp32/bf16 比較が無効 | 自作の再開機能がキャッシュ結果を再利用した | 比較は必ず空の出力ディレクトリで実行する |
