# 担当外への依頼（受信箱）

> **このページは「手順と書式」です。規範（鉄則）は
> [記述ルール](../style-guide.md) の §B-5 にあります。重複ではなく分担です。**
>
> ## 鉄則
>
> **担当外のページを直したいときは、commit メッセージに書くだけでは不十分です。**
> 依頼は**相手の受信箱（このディレクトリの `<呼び名>.md`）に追記**してください。
> commit メッセージは流れて消えますが、受信箱は残るためです。
> 担当を分けたうえで依頼が確実に届くことが、分担を成立させる条件です。

## 1. 誰が書いてよいか

| 操作 | できる人 |
|---|---|
| 他人の受信箱に**追記**する | **誰でも可**（担当ページの規則の唯一の例外。依頼が届かないと分担が壊れるため） |
| 受信箱の既存行を**書き換える・消す** | その受信箱の持ち主**だけ** |
| 「状態」を「対応済み」に更新する | その受信箱の持ち主（依頼を処理した本人） |

**行は消しません。** 経緯が要るため、状態だけを更新して残します。

## 2. 書き方

受信箱に、次の形で**日付ごとの節**を追記します。

```markdown
## YYYY-MM-DD <呼び名> より

| # | 対象ページ | 直したい点 | 提案 | 根拠 | 状態 |
|---|---|---|---|---|---|
| 1 | conflicts.md | 参照が古い | 「§9」→「§E」 | style-guide.md の E-1 対応表 | 未対応 |
```

- **根拠**には、実測値・ファイル名・節を書きます。根拠のない依頼は受け取れません。
- 状態は **未対応 / 対応中 / 対応済み / 見送り（理由）** のいずれかです。
- 依頼が多くても、**対象ページごとに分けて**書きます。

## 3. 受信箱の一覧

| 呼び名 | 機械 | 受信箱 |
|---|---|---|
| AG-GB10 | spark-c083（GB10） | [AG-GB10.md](AG-GB10.md) |
| AG-MAC | Mac mini M4 Pro | [AG-MAC.md](AG-MAC.md) |
| AG-GH | GitHub noreply の機械 | [AG-GH.md](AG-GH.md) |

呼び名と担当ページの全体は [執筆者名簿とページ担当](../owners.md) を参照してください。

## 4. なぜ commit メッセージでは足りないか

同じ日に、依頼を commit メッセージにだけ書いたために届かず、
**同じ指摘が後から繰り返された**例がありました（[競合の記録](../conflicts.md) の §4 を参照）。
以降、依頼は必ず受信箱に置きます。
